# M1 model decision

Extraction, consolidation, and rerank use OpenRouter via AI Gateway, with OpenAI as fallback. Chat remains GPT-5.6 Luna at reasoning effort `high`.

This milestone pins the other three jobs from the eval set in `m1-set.json` (24 hand-labeled documents, all six memory kinds). The harness is `packages/memory/src/eval.ts` and `eval-run.ts`. Unit tests score the heuristic extractor so CI stays honest without an API key. Live candidate runs:

```sh
OPENROUTER_API_KEY=… bun run eval:m1
```

`OPENAI_API_KEY` is optional fallback.

That sweep writes per-document input, output, reasoning, and cached-input tokens to `docs/eval/m1-results.json` and refreshes this file. `packages/cf-runtime` records Responses API `usage` on every structured call (`Llm.drainUsage()`).

## Candidates considered

| Job | Candidates | What we scored |
|---|---|---|
| extract | Luna `none` / `low` / `medium`; Terra `low` | memory precision/recall vs input+output+reasoning tokens per document |
| consolidate | Luna `none` / `low` | new vs duplicate accuracy on extracted memories |
| rerank | Luna `none` / `low` | whether the gold memory is ranked first, plus latency |

Luna `high` is omitted from the default extract sweep: it is the volume job, and `high` reasoning tokens would dominate cost.

## Pins

Until a keyed `eval:m1` run replaces them, pins stay the cost-aware defaults (Luna is the cheapest 5.6 tier):

| Job | Model | Effort | Why |
|---|---|---|---|
| chat | `gpt-5.6-luna` | `high` | already locked |
| extract | `gpt-5.6-luna` | `low` | dominant cost line; `low` keeps reasoning tokens from dominating |
| consolidate | `gpt-5.6-luna` | `low` | same model as extract so the static system prompt + schema stay in the prompt cache |
| rerank | `gpt-5.6-luna` | `none` | on the chat/recall latency path |

Config: `defaultLlmConfig` in `packages/domain/src/llm.ts`. Re-run `bun run eval:m1` with `OPENROUTER_API_KEY` (and optional `OPENAI_API_KEY`) before changing these pins.
